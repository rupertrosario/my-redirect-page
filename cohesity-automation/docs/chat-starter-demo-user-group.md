# Chat Starter — User & Group Review Demo

This is a self-contained demo. No MCP needed. No infrastructure setup.  
Your colleague runs an existing PowerShell script from the NAS share, uploads the CSV output, and Claude does the analysis.

---

## Step 1 — Colleague runs the script

Script is already on the NAS share. They run it from PowerShell:

```powershell
# Standard run — hits all clusters via Helios
.\Get-CohesityUsersGroupsRoles.ps1

# Output goes to the configured output directory (CSV file)
# Share the CSV file path so it can be uploaded to Claude
```

If the script needs parameters (API key path, output path), use whatever is already configured on that machine — do not change the script.

---

## Step 2 — Open a new chat in the "Backup Cohesity Architect" project

Paste this as your opening message:

---

```
I am doing a proof-of-concept demo of the Cohesity intelligent automation platform.
Read `claude/cohesity-architect-plan.md` from this project for background context.

I am attaching a CSV produced by our Cohesity user and group review PowerShell script.
This script runs GET-only against Cohesity Helios and outputs users, groups, and roles across all clusters.

## Your role

You are a backup audit analyst. Analyse the attached CSV and produce a structured audit report.

## Strict rules — MUST follow

1. Only report what is in the CSV. Do not infer, assume, or fill in missing data.
2. If a field is empty or missing, write NOT_FOUND. Never guess.
3. Every finding must cite the exact column name and value from the CSV.
4. Do not reference any cluster, user, group, or role that is not in the attached data.
5. If the CSV appears incomplete or truncated, say so at the top of the report before any findings.

## Audit checks to apply

Flag the following. For each flag, state: what was found, which row (cluster + user/group), which column, recommended action.

USERS:
- Users with admin or super_admin role (flag for review — should be minimal)
- Users with no last_login recorded (flag as unverified active status)
- Users inactive more than 60 days (last_login older than 60 days from today: 2026-08-06)
- Users added in the last 30 days (new accounts — flag for awareness)
- Service accounts (non-human accounts) with elevated roles

GROUPS:
- Groups with 0 members (orphaned groups)
- Groups with no description or owner recorded
- Groups with admin role assigned

CROSS-CHECK:
- Users with roles that do not match any group they belong to
- Any cluster where no users are recorded (possible data gap — not a clean result)

## Output format — use exactly this structure

### Coverage
- Clusters in data: [list]
- Total users found: N
- Total groups found: N
- Data completeness: [any gaps or warnings]

### Critical Flags (action required)
[table: Cluster | User/Group | Role | Issue | Recommended Action]

### Advisory Flags (review recommended)
[table: Cluster | User/Group | Role | Issue | Recommended Action]

### Clean Items
[one-line summary of what looks normal — do not list every clean row]

### Audit Statement
"This report is based solely on data from the attached CSV produced on [date from filename or NOT_FOUND].
Coverage: [N clusters]. Generated by Claude for human review. Not for automatic closure."
```

[Attach the CSV file here]

---

## Step 3 — Review the output

Claude will produce a structured findings report. Review it. If anything looks wrong or hallucinated — a cluster name that does not exist, a user not in your environment — flag it immediately. That is how we validate the guardrails before going further.

---

## What this demo proves

- Claude can analyse real Cohesity data with no MCP, no infrastructure, no build work
- The audit rules work and produce consistent structured output
- The guardrails prevent Claude from fabricating findings
- The output is Jira-comment-ready or Teams-message-ready
